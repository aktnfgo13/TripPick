# 구성과 의존 방향
두 클라이언트는 같은 버전의 HTTP 계약을 소비한다. 차량 화면은 Compose와 ViewModel, 휴대폰은 Vue와 API 클라이언트로 구분한다. 모바일 개발 서버가 /api를 FastAPI로 프록시한다. 운영은 동일 출처 HTTPS를 전제로 한다.
서버는 한 프로세스로 시작한다. API는 입력·인증, 서비스는 여행/사진/투표/앨범별 트랜잭션, 저장소는 쿼리와 영속화를 담당한다. 초기에는 준비 상태와 저장 어댑터만 구현한다. 향후 DB 저장소 뒤에 PostgreSQL, 객체 저장 포트 뒤에 비공개 R2를 둔다. 분석 작업은 사진 등록과 같은 트랜잭션으로 큐에 넣고 독립 worker가 재시도한다. PhotoAnalyzer 입력은 원본 핸들, 출력은 버전·점수·해시·그룹 후보이다.
차량 SDK는 차량 앱 어댑터 내부에서만 초기화·해제한다. 권한 거부, 연결 실패, 위치 결측은 기록 불가로 표현한다. 지도 렌더러는 지역 코드와 장소 목록을 입력으로 받고 SDK를 직접 조회하지 않는다. 재시작 시 서버 상태와 마지막 선택을 복원한다. 차량은 크기가 제한된 미리보기 캐시와 지연 목록을 사용한다.
휴대폰은 Secure/HttpOnly/SameSite 세션과 변경 요청의 Origin/CSRF 검사를 거친다. QR 초대와 소유권 증명은 별개인 단기 토큰이다. 관리자 재접속은 복구 가능한 계정에 연결한다. 서버가 요청마다 여행 멤버십과 역할을 확인한다. 로그에 초대·서명 URL, 토큰, 사진·GPS를 남기지 않는다. 공유용 미리보기에서 EXIF를 제거한다. 사용자 삭제 요청과 보관 기간 처리를 분리한다.
